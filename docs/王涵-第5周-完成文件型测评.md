# 王涵-第5周-完成文件型测评

## 1. 本周工作目标

按照项目工作计划，第 5 周我负责完成 `B3` 模块中的“文件型测评”能力。  
本周目标是让系统不再只看命令文本，而是能够在受控环境中真实执行提交内容，并对文件题的输出结果、文件状态和权限变化进行联合判定。

当前阶段我们把重点放在以下几类题目上：

- 文件查看类
- 文件复制 / 改名类
- 文本处理类
- 文件权限修改类

## 3. 本周成果

### 3.1 文件题判题方式从“静态猜测”变成“动态验证”

现在系统会先在临时目录中准备测试文件，再执行学生提交，最后比对：

- 标准输出是否正确
- 目标文件是否生成
- 目标文件内容是否正确
- 只读文件是否被修改
- 不应存在的旧文件是否仍然存在

这意味着像 `cp`、`mv`、`chmod` 这类题目，已经可以按“执行结果”评分，而不是只按命令关键词评分。

### 3.2 文件型题目的配置方式已经明确

本周把文件题的关键配置统一进了题库结构中，主要字段包括：

- `question_type`
- `input_files_json`
- `expected_files_json`
- `readonly_paths`
- `writable_paths`

这样后续新增文件型题目时，优先补配置即可，不需要频繁重写判题流程。

### 3.3 已完成的典型题目

- `Q05`：`head/tail/ls/cp/mv` 文件查看、复制、改名
- `Q06`：`vi` 参数编辑与 `chmod` 权限修改
- `Q07`：`grep + sort` 文本处理
- `Q08`：`sed` 文件读取与筛选
- `Q09`：`awk` 文件统计与筛选

## 4. 具体实现方式

### 4.1 先在题库中定义文件题需要的输入和预期结果

文件型测评不是直接拿一段命令就执行，而是先在题库里把测试环境描述清楚。  
本周已经把文件题的输入文件和预期文件结果写入了题库蓝图。

文件位置：

- `app/seed_data.py`

例如 `Q05` 的配置中，已经明确了输入文件、预期输出和预期生成文件：

```python
{
    "id": "Q05",
    "question_type": "file",
    "allowed_commands": ["head", "tail", "ls", "cp", "mv"],
    "metadata_json": {
        "absent_paths": ["week5_15.log"],
        "readonly_paths": ["week5_11.txt", "week5_12.txt", "week5_14.log", ".hidden", "week5_14_dest/.keep"],
    },
    "cases": [
        {
            "input_files_json": {...},
            "expected_files_json": {
                "week5_14_dest/week5_14.log": "copy me\\n",
                "week5_15.txt": "rename me\\n"
            }
        }
    ],
}
```

### 4.2 评测前自动生成临时工作区

本周在执行器里补上了文件工作区准备逻辑。  
系统会先创建临时目录，把测试用例里的输入文件写进去，再根据元数据设置权限。

文件位置：

- `app/judge/dynamic_runner.py`

关键实现点：

- `_write_tree()`：写入输入文件树
- `_apply_path_permissions()`：设置只读 / 可写权限
- `_prepare_command_workspace()`：为文件题准备测试环境

其中权限控制逻辑如下：

```python
readonly_paths = set(metadata.get("readonly_paths", []))
writable_paths = set(metadata.get("writable_paths", []))

for relative_path in input_paths:
    target = workspace / relative_path
    if relative_path in writable_paths:
        target.chmod(0o644)
    elif relative_path in readonly_paths:
        target.chmod(0o444)
```

### 4.3 执行后同时检查输出和文件结果

为了让文件题判定更可靠，本周没有只看 `stdout`，而是加上了文件状态检查。

文件位置：

- `app/judge/dynamic_runner.py`

主要检查项包括：

- `_collect_expected_files()`：检查应生成文件是否正确
- `_snapshot_paths()`：执行前记录只读文件快照
- `_collect_readonly_modifications()`：执行后检查只读文件是否被改动
- `_verify_shell_case()`：汇总输出、文件、副作用并生成判定结果

以 `Q05` 为例，系统会同时验证：

- `week5_14_dest/week5_14.log` 是否被复制出来
- `week5_15.log` 是否已经被改名消失
- `week5_15.txt` 是否存在且内容正确
- 标准输出是否与预期一致
